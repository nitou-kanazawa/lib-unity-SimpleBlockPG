# 07-InputBlocks

**入力値とブロック固有データが保存・復元されることを確かめるデモ。**

`06-Playground` はブロックの組み立てそのものを見るためのシーンなので、こちらは分けてある。既存シーンには手を入れていない。

## 触って確かめられること

| 操作 | 確かめられること |
| --- | --- |
| 入力欄に値を入れて **Save → Clear → Load** | 入力値が保存データをまたいで戻る |
| 入力欄を編集して **Undo** | 編集前の値に戻る |
| 右クリック（スマホは長押し）→ **色を変える** → Save → Clear → Load | ブロック固有データが保存される |
| Scope に入れて **折り畳む** | 畳んでも中身と入力値が失われない |
| ブロックを **複製** | 入力値と色ごと複製される |
| テーマを切り替え | 入力欄もテーマに追従する |

右のパネルには、**保存されるのと同じ内容**が常に表示される。Save を押さなくても、何が保存対象になっているかが分かる。

## ブロック

このデモ専用のプレハブ（`Resources/BlockPG/`）。

| プレハブ | 入力 | 保存される値 |
| --- | --- | --- |
| `Block [Say]` | `TMP_InputField` | 入力文字列 |
| `Block [Wait]` | `TMP_InputField`（数値） | 数値の文字列表現 |
| `Block [Move]` | `TMP_Dropdown` | 選択肢の**文字列** |

`Block [Entry]` と `Block [Scope]` はライブラリ同梱のものをそのまま使う。

### ライブラリ側に入れていない理由

同梱プレハブに入力を足すと、既存デモの見た目が変わる。入力ブロックの構成はアプリごとに違うため、ライブラリは**入力コンポーネントだけ**を提供し、プレハブは利用側が組む形にしている。

## 色替えについて

`DemoBlockTint` は `I_BPG_BlockCustomData` の実装例。入力値では表せない情報をブロックに持たせて保存する、という使い方を示している。

```csharp
public string SaveCustomData() => HasTint ? _index.ToString() : string.Empty;
public void LoadCustomData(string data) => _index = int.TryParse(data, out var i) ? i : -1;
```

ブロックと同じ `GameObject` に付けるだけで、保存データへ一緒に書き出される。

## 実装メモ

**入力値の Undo は「編集の開始」で記録している。** 値が変わってから記録したのでは、取り消し先が変更後の値になってしまう。入力欄は `onSelect`、ドロップダウンは押下を捉えている。

**復元はプレハブからの生成で行う。** 実行時に付けたコンポーネントは復元後のブロックには残らない。入力も `DemoBlockTint` もプレハブ側に置いてある。

**ブロック内の文字は ASCII にしてある。** TMP の既定フォント（LiberationSans SDF）に日本語のグリフが無いため。日本語を入れる場合は日本語を含むフォントアセットを用意する。パレットや説明文は uGUI の `Text` なので日本語のまま表示される。

**GhostBlock から `LayoutGroup` を外してある。** `06-Playground` の GhostBlock には撤去前の `LayoutGroup` が残っている（ブロック本体からは全て撤去済み）。こちらでは外した状態で置いている。
